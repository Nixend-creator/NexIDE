# NIXEND Developer Skill

1. Перед редагуванням прочитай локальний код і conventions.
2. Нові файли створюй Kotlin; не переписуй на Kotlin наявний Java-код без потреби.
3. Дотримуйся 2-пробільних відступів, максимум 140 символів на рядок, `else`/`catch`/`finally` на новому рядку.
4. Використовуй `my` для instance-змінних і `our` для static/class-змінних.
5. Додавай Apache 2.0 copyright-заголовок та ім'я контриб'ютора до кожного нового файлу.
6. Використовуй null-safety, data/sealed classes та extension functions, коли це справді покращує код.
7. Не створюй API на основі здогадів: перевір наявні залежності та приклади в репозиторії.
8. Не додавай незв'язане форматування, rename або move.
9. Нові OpenAPI документуй KDoc/Javadoc.
10. Після реалізації переглянь diff і видали незавершений код та TODO, внесені зміною.
