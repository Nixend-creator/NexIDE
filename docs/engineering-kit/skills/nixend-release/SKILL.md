# NIXEND Release Readiness Skill

1. Переконайся, що patch містить одну логічну зміну.
2. Переглянь весь diff; видали незавершений код і TODO, внесені задачею.
3. Перевір, що не додано `.idea/*` / `codeStyleSettings.xml` без необхідності.
4. Уникай зайвих rename/move; перевір зворотну сумісність.
5. Переконайся, що тести, інспекції та форматування виконані або чесно позначені як невиконані.
6. Перед push — squash; бажаний результат — один коміт із чітким повідомленням.
7. Запропонуй коротке повідомлення коміту лише на основі фактичного diff.
8. Не оголошуй реліз готовим, якщо критичні перевірки не виконані.
