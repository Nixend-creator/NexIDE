# NIXEND Documentation Skill

1. Для кожного нового OpenAPI — інтерфейсу, класу, методу або extension point — додай KDoc/Javadoc з призначенням і параметрами.
2. Для внутрішнього коду документація бажана, але не обов'язкова.
3. Документуй фактичну поведінку, обмеження та сумісність; не обіцяй непідтверджених можливостей.
4. Дотримуйся термінології проєкту та його наявного стилю документації.
5. Оновлюй документацію лише в межах логічної зміни.
