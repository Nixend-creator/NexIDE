# NIXEND IDE Engineering Skills Kit

Комплект Skills та інструкцій для Claude і Grok для розробки IDE-аналога IntelliJ IDEA.

**У цьому репозиторії (NexIDE):** див. `NEXIDE.md` — мапінг на Compose Desktop / Gradle, замість збірки проти `intellij-community`.

## Джерело стандарту

Основний нормативний документ: `standards/INTELLIJ_PLATFORM_CODING_GUIDELINES_1.0.md`, підготовлений за завантаженим користувачем файлом **IntelliJ Platform Coding Guidelines — IDE Analog Development Standard, версія 1.0, вересень 2026**.

Увага: вихідний документ містить короткий набір правил на 3 сторінках. Цей комплект перетворює їх на операційні інструкції для агентів. Пункти, явно позначені як «практична процедура комплекту», є організаційними рекомендаціями цього комплекту, а не дослівними вимогами вихідного документа.

## Структура

- `CLAUDE.md` — головні інструкції для Claude Code.
- `GROK.md` — головні інструкції для Grok.
- `AGENTS.md` — універсальні правила для агентів, які читають AGENTS.md.
- `standards/` — нормалізований стандарт і контрольний список.
- `skills/` — модульні навички у форматі `SKILL.md`.
- `templates/` — шаблони задачі, PR/patch та звіту аудиту.

## Як застосувати

1. Комплект уже лежить у `docs/engineering-kit/` (NexIDE).
2. Перегляньте `standards/INTELLIJ_PLATFORM_CODING_GUIDELINES_1.0.md` і підтвердьте, що це ваш активний стандарт.
3. Для Claude Code використовуйте `CLAUDE.md`; за потреби скопіюйте потрібні каталоги з `skills/` до `.claude/skills/`.
4. Для Grok використовуйте `GROK.md` як project/system instructions, а потрібний `SKILL.md` додавайте до контексту конкретної задачі. Якщо середовище Grok підтримує імпорт навичок, імпортуйте каталоги з `skills/`.
5. У будь-якому агенті спочатку доручіть прочитати `AGENTS.md`, стандарт і відповідну навичку.
6. Перед комітом виконайте контрольний список із `standards/REVIEW_CHECKLIST.md`.

## Важливі обмеження

- Комплект не стверджує, що самостійно запускає тести або IDE-інспекції. Агент має виконати доступні команди, якщо середовище дозволяє, і чесно повідомити про невиконані перевірки.
- Не вигадуйте API IntelliJ Platform, версії залежностей, результати складання чи тестів.
- Вихідний стандарт вимагає будувати й тестувати проти останньої версії `intellij-community`; якщо локально неможливо визначити або отримати її, повідомте про це, не підміняючи факт припущенням.
